# What can be signed from the recorder?

Target: the **bare JSON** presentation in [draft-noa-scitt-ai-agent-receipt-01, §§2–5](https://datatracker.ietf.org/doc/html/draft-noa-scitt-ai-agent-receipt-01#section-3), wire label `noa.receipt/0.1`. This is an individual Internet-Draft, not IETF approval or certification. The [source recorder at the reviewed revision](https://github.com/cincinnatus-management/action-evidence-pilot/blob/1e0889b13394c78dc3ed755ff0d0b31a4e4b2ebd/action_evidence.py#L59-L123) makes **unsigned** records. A signature made today cannot authenticate the author of yesterday's log. Generate receipts only for a fresh invocation of that recorder under the following declared issuer settings, not by silently backfilling the historical sample.

| Recorder field or check | Decision for this evaluation |
|---|---|
| `seq` | Check the original 1-based sequence. In a separate chain, start at 0 (§5). |
| `at` | Recorder time, not a trusted clock. Preserve in source; `ts` is when the adapter records its new receipt (§3.1). |
| `agent` | Copy the configured label to `agent.id`. It identifies no human. The issuer uses `principal=POLICY` for this policy-driven workflow. No model or identity manifest. |
| `action.type`, `.url` or `.path`, `.why` | Use the operation name for `action.id` and the local risk-table key `action.canonical`. `paramsHash` is SHA-256 of recorder `canon(action)` including the reason; never put raw values in a receipt. This is a local commitment, not a shared action digest. Only the bundled public workflow is supported. |
| `policy_id`, `policy_sha256` | Verify both against the pinned local policy. Keep them in the source commitment. Omit `ruleId` (the policy is not an individual rule) and the optional `compliance` block (no recorded policy read set). |
| `decision`, `decision_reason` | Re-evaluate `allowed(action, policy)` and compare both fields. Map allowed → `ALLOWED`, denied → `BLOCKED`, irrespective of the network result. Never upgrade permission to proof of execution. |
| `result.status`, `.bytes`, `.blocked`, `.error`; `evidence.file`, `.sha256` or null | Outside the closed receipt schema. Rehash the expected numbered evidence file when present; check byte count. The source digest binds result and evidence references, not the truth of a remote report. |
| `cost.seconds`, `.power_usd`, `.hardware_wear_usd`, `.internet_usd`, `.model_usd`, `.total_usd` | Source-only estimates, including fractions. Do not put them in the integer-only receipt. |
| `prev_hash`, `record_hash` | Recompute original zero-sentinel chain over recorder canonical bytes, including every source field except `record_hash`. Use `id=record-<record_hash>` to bind the new signature to that source. Original hashes are **not** draft chain hashes. |
| Recorder `verify` and summary | Original checks: previous link, recomputed record hash, referenced file digest; no signer, external anchor, or completeness check. New verifier performs these checks on fixed local filenames, checks the pinned workflow length/order and recomputes the receipt projection. Summary counts, costs and head are derived displays, not inputs to trust. |
| Buyer probe | Its repository/commit pins, published artifacts, separate payment-key signature, optional page and channel ZIP checks stay separate. A payment-key signature is not an action signature. The Docker wrapper is a way to run the recorder; MCP uses another policy/action shape and is not accepted by this adapter. |

Issuer choices fixed **before** this run: governance `on`, `sandboxed=false` (real read-only network workflow); local risk table `http_get=LOW`, `write_file=HIGH` for the requested operation, including denials. `reversible=false` means the issuer offers no rollback for either operation. These classifications are declarations of this adapter, not facts recovered from an old record. No tenant, rollback reference, approval, or asserted policy compliance. New random scope per run. Native Ed25519 signature over §4.2's tagged raw digest, a separate new key per invocation. Local public-key/terminal-hash pin is not a §5.2 signed checkpoint. No COSE envelope, RFC 9943 Signed Statement, transparency registration, or SCITT Transparency Receipt is produced.

The verifier is for this one producer and workflow, not an implementation of all draft verifier roles. No claim of standards compliance, interoperability with another implementation or production key custody. A bare record cannot establish named pre-execution approval, independent downstream outcome, physical completion, or that an agent acted correctly (§§1.5, 8–9). The verifier reports these limits separately from signature validity.
