# Comparison boundary: draft-sharif-agent-audit-trail-11

Source: [individual Internet-Draft, revision 11, §§3–8](https://www.ietf.org/archive/id/draft-sharif-agent-audit-trail-11.txt), text SHA-256 `377ed33392a8657f936a9bf13dbaaa5efb6bacbabcd8a0d62600248210d5e902`. This is a native Cincinnatus example, **not an AAT wire format, AAT validator, IETF standard, endorsement, certification, conformance assessment or proof of a buyer deployment**. It does not upgrade the [historical release](https://github.com/cincinnatus-management/action-evidence-pilot/releases/tag/evidence-kit-v1.0.0).

| Draft area | What this run establishes; what is missing |
|---|---|
| §3.1 Identity | New `record_id` and `session_id` UUIDs, plus the recorder role and format version. No AAT `agent_id` URI, semantic `agent_version`, or `principal` (`principal_type`, `principal_id`, `authority_ref`). A local allow list is not a signed grant. No `trust_level` assigned; the writer has no cryptographic identity. |
| §§3.1, 4 Event | `timestamp`, `parent_record_id`, `prev_hash`; native `event`, `detail`, `phase` and decision/status fields, not draft `action_type`, `action_detail`, `record_phase` and `outcome`. The allow is a successful **policy match**, not a claim that the read succeeded. Denial is recorded before skipping the request. No escalation, delegation, high-risk workflow or external state change is demonstrated. |
| §3.2 Optional fields | Native `seq` rather than `sequence_number`; local denial reason rather than `deny_reasons`; local file digest rather than general `input_hash`, `output_hash` or `content_fingerprint`. No `human_override`, `risk_score`, `model_id`, `latency_ms`, `cost_estimate`, `sanctions_check`, `jurisdiction`, `nonce`, `external_timestamp`, `prior_generation_tail`, `recording_component`, `trust_assignment`, `batch`, `platform_attestation`, `signature`, `sig_alg`, `signer_kid`, `signature_classical` or `signer_kid_classical`. No replay service or trusted clock. |
| §§5–6 Trust and integrity | Same-process writer and reader; no separate security principal, protected signing key, trust authority, attested platform or L1–L4 claim. No consequential-action classifier or downgrade. Canonical bytes are specified for this restricted local format; no general RFC 8785/JCS parser, signature verification, key resolution, Merkle inclusion or external anchor. A verifier in another shell is **not** an independent recorder. An observer-held hash narrows later comparisons; a final bundle alone cannot prove temporal order against a dishonest writer. |
| §7 Type-specific detail | Fixed local read, not an external tool or MCP call. No draft `tool_call`/`tool_response` pair, `tool_name`, `tool_server`, `parameters_hash`, `tool_version`, `authorization` or `parent_call_id`; native byte count/hash rather than `response_size`/`response_hash`. Exact-match reason, artifact and policy digest, not draft `decision_type` or `policy_ref`. The result links to its decision by `authorization_record_id`; it is not independent authority. No `reasoning_hash`, `confidence`, `alternatives_considered`, delegation, escalation, structured error payload or general lifecycle transitions. |
| §8 Session | One serial session, start/close, null genesis links, local sequence, count and session digest. No duration measurement, heartbeats, declared cadence, concurrent branches, generation continuity, gap recovery, synthetic close or signed completeness statement. An unclosed trail cannot pass closed verification. A closed fixture does not prove no other action occurred. |

Not evaluated: general draft schemas, other revisions, retention, transport, privacy controls, legal compliance, hardware durability after power loss, hostile local filesystems, identity, production enforcement or customer use. Only the fields and workflow listed in the buyer guide are implemented.
